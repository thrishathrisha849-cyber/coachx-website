| 5 | Category hierarchy depth limit | **RESOLVED (spec-alignment correction)** — capped at 2 levels (`MAX_CATEGORY_DEPTH = 2` in `category.service.ts`), matching 004 FR-014's literal "category, subcategory" naming. Enforced both directions: a category cannot receive a parent that already has its own parent, and a category with existing children cannot itself be assigned a parent. **Status-code contract** (pre-Phase-7 stabilization correction): `assertParentValid` checks self-parent (400) and unknown-parent (400) first, then — only on update, where a cycle is structurally possible — the ancestor-cycle check (409, since a proposed parent that is a descendant of the category being updated is a structural conflict) BEFORE the depth-cap checks (400). This ordering matters: a direct 2-node cycle (make a category the parent of its own child) always also fails the "chosen parent must be a root" depth-cap rule, since a non-root descendant inherently has a parent — checking depth-cap first would always shadow the more specific 409 with a generic 400.
